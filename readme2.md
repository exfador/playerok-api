## Кратко

В версии **2.0.3** переработан блок обновлений и добавлен импорт расширений прямо из Telegram-панели. Раньше для подключения нового расширения нужно было лазить в файловую систему сервера и руками класть папку в `ext/`; теперь можно отправить zip-архив боту и получить готовое расширение в один шаг.

Также появился переключатель «Авто-установка» — если он включён, бот сам скачает новую версию на старте и перезапустится без вашего вмешательства. Уведомления о новых релизах теперь имеют отдельный тумблер (раньше управлялись только общим флагом `alerts.on.update`).

Параллельно обновлены SHA-256 хеши persisted GraphQL-запросов под текущую схему playerok.com — без этого `user`, `deal` и `gameCategoryInstructions` начали возвращать `PersistedQueryNotFound`.

## ✨ Добавлено

### 🔃 Раздел «Обновления» в меню «Настройки»

В Telegram-панели в разделе **«⚙️ Настройки»** появился новый пункт **«🔃 Обновления»** с двумя переключателями:

| Переключатель | Что делает |
|---|---|
| **⬇️ Авто-установка** | Бот будет автоматически обновляться до последней версии при запуске (не во время работы). По умолчанию — **выкл**. |
| **🔔 Оповещать** | При выходе новой версии вам придёт уведомление сюда в Telegram с кнопкой «📥 Загрузить и применить». По умолчанию — **вкл**. |

Соответствующие ключи в `conf/config.json`:

```json
{
  "updater": {
    "enabled": true,
    "interval_sec": 3600,
    "auto_update": false,
    "notify": true
  }
}
```

При обновлении со старого конфига оба новых ключа допишутся со значениями по умолчанию автоматически (механизм `need_restore` в [`lib/cfg.py`](lib/cfg.py)).

### 🚀 Авто-установка обновления на старте

Если в настройках включена **«⬇️ Авто-установка»**, при старте `main.py` (после интерактивного мастера, но **до** запуска движка магазина и Telegram-панели) бот:

1. Дёргает GitHub Releases и сравнивает теги через `lib.updater.is_newer`.
2. Если новее — скачивает архив релиза, распаковывает во временную папку, копирует файлы в проект (с тем же набором `_PRESERVE`, что и при ручном обновлении: `conf/`, `db/`, `logs/`, `__pycache__`, `.git`, `.venv` не трогаются).
3. Сохраняет в `db/updater_state.json` метку `last_applied_tag`/`applied_at`.
4. Запускает `schedule_reboot(2.0)` — процесс корректно перезапускается, выставляя `CXH_FAST_REBOOT=1` (в баннере на старте видно «↻ Перезапуск»).

Логика реализована в `CXHBot._startup_auto_update()` в [main.py](main.py). Если по дороге что-то ломается (нет сети, прокси падает, GitHub возвращает не 200) — старт продолжается как обычно: пишется warning, бот никуда не падает.

### 🔔 Отдельный тумблер уведомлений о новых релизах

Раньше уведомления о новых версиях управлялись только общим флагом `alerts.on.update`. Это было неудобно: чтобы заглушить именно «спам про апдейты», приходилось копаться в общем разделе уведомлений.

Теперь в `bot/core.py` в фоновой задаче `_update_check_loop()` уведомление отправляется, только если **оба** флага включены:

```python
alerts_on = alerts.get('enabled', True) and (alerts.get('on') or {}).get('update', True)
notify_on = bool((self.config.get('updater') or {}).get('notify', True))
if alerts_on and notify_on and is_newer(rel.tag, _VERSION) and ...:
    panel.notify_update(...)
```

Выключить именно «уведомления об апдейтах», оставив все остальные алерты включёнными, можно одним нажатием в разделе **«🔃 Обновления»**.

### 🔄 Обновлены GraphQL persisted-query хеши

В словаре `PERSISTED_QUERIES` ([pok/gql.py](pok/gql.py)) под актуальную схему playerok.com обновлены sha256-хеши и добавлен новый запрос:

| Запрос | Что обновилось |
|---|---|
| `user` | Новый хеш — старый возвращал `PersistedQueryNotFound`, ломая карточку профиля и поиск по нику. |
| `deal` | Новый хеш — открытие конкретной сделки и подгрузка её деталей. |
| `gameCategoryInstructions` | Свой хеш (раньше по ошибке использовался хеш `gameCategoryObtainingTypes` — наследие старой схемы). |
| `messageTemplates` | **Новый** ключ — для запроса шаблонов сообщений с сервера. |

Остальные 19 хешей остались прежними. Если у вас была версия 2.0.2 и запросы недавно начали возвращать `PersistedQueryNotFound` — после апдейта на 2.0.3 это пройдёт.

### ➕ Импорт расширения из Telegram-панели

В разделе **«🧩 Расширения»** в Telegram-боте появилась кнопка **«➕ Импортировать»**. Сценарий:

1. Жмёте кнопку — бот переключается в состояние ожидания файла и пишет инструкцию.
2. Отправляете в чат **zip-архив документом** с папкой расширения внутри (либо архив, где `__init__.py` лежит в корне — тогда имя папки берётся из имени файла).
3. Бот:
   - валидирует пути (отказ при `..`, абсолютных путях и `__MACOSX/`),
   - находит все корневые папки с `__init__.py`,
   - распаковывает их в `ext/` (если папка с таким именем уже есть — она будет заменена),
   - отвечает списком импортированных расширений и просит перезапуститься.

После перезапуска бот сам прогонит `lib.ext.discover_extensions()` и подключит новые модули; включить/выключить их можно из того же раздела «🧩 Расширения».

## 🐛 Исправлено

- **GraphQL `PersistedQueryNotFound`** на запросах `user`, `deal`, `gameCategoryInstructions` — sha256-хеши обновлены под текущую схему API.
- **`gameCategoryInstructions` дублировал хеш `gameCategoryObtainingTypes`** — теперь у запроса собственный хеш (`5991cead…`).
- **Гонка флагов уведомлений.** При включённых общих алертах уведомления о новых релизах слали даже тем, кто хотел их выключить отдельно. Теперь блок управляется собственным тумблером и не зависит от настроек алертов про чаты/сделки/отзывы.
- **Безопасные пути в импорте.** Импорт расширения проверяет zip на zip-slip-уязвимости: пути с `..`, абсолютные пути и `\` отбраковываются с понятной ошибкой ещё до распаковки.

## 🔧 Как обновиться

Если у вас уже стоит 2.0.x:

1. В Telegram-боте перейдите в **«🛠 Система»** → **«🔄 Проверить обновления»** → **«📥 Загрузить и применить 2.0.3»**. Бот скачает релиз и сам перезапустится.
2. Либо вручную: `git pull` (если ставили из git) или скачайте zip с GitHub и распакуйте поверх. Папки `conf/`, `db/`, `logs/` трогать не нужно — они переживут обновление.

После обновления зайдите в **«⚙️ Настройки» → «🔃 Обновления»** и решите:

- хотите ли получать уведомления о новых версиях (по умолчанию — **да**),
- хотите ли, чтобы бот сам ставил обновления на старте (по умолчанию — **нет**).
